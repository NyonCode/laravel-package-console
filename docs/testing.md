## The test setup

`package:init` (unless you pass `--no-tests`) sets up [Pest](https://pestphp.com) on
[Orchestra Testbench](https://packages.tools/testbench), which boots a real Laravel application
around your package:

```php title="tests/TestCase.php"
<?php

namespace Acme\Blog\Tests;

use Acme\Blog\BlogServiceProvider;
use Illuminate\Foundation\Application;
use Illuminate\Support\ServiceProvider;
use Orchestra\Testbench\TestCase as Orchestra;

abstract class TestCase extends Orchestra
{
    /**
     * Get the package service providers.
     *
     * @param  Application  $app
     * @return array<int, class-string<ServiceProvider>>
     */
    protected function getPackageProviders($app): array
    {
        return [
            BlogServiceProvider::class,
        ];
    }
}
```

```php title="tests/Pest.php"
<?php

use Acme\Blog\Tests\TestCase;

pest()->extend(TestCase::class)->in(__DIR__);
```

Every test in `tests/`, Feature and Unit alike, runs inside the Testbench application with your
provider loaded. `phpunit.xml` sets the environment for it:

| Variable | Value | Why |
|---|---|---|
| `APP_ENV` | `testing` | |
| `APP_KEY` | a random key generated by `package:init` | requests through the `web` middleware group encrypt cookies |
| `DB_CONNECTION` | `testing` | Testbench's in-memory SQLite connection |

Two tests are included:

- `tests/Feature/ServiceProviderTest.php` checks that the service provider is registered.
- `tests/ArchTest.php` forbids `dd`, `dump`, `ray` and `var_dump` anywhere in the package.

Run them with:

```bash
composer test        # vendor/bin/pest
```

## make:test

```bash
php anvil make:test PostApi                     # tests/Feature/PostApiTest.php (Pest)
php anvil make:test Support/Slug --unit         # tests/Unit/Support/SlugTest.php
php anvil make:test Http/PostApi --phpunit      # a PHPUnit class
```

| Argument / option | |
|---|---|
| `name` | The test name. `Test` is appended when missing, and each segment is capitalised. Nest with `/`. |
| `-u`, `--unit` | Put the test in `tests/Unit` instead of `tests/Feature` |
| `--phpunit` | Create a PHPUnit test class instead of a Pest test |
| `-f`, `--force` | Overwrite an existing file |

```php title="tests/Feature/PostApiTest.php"
<?php

it('works', function () {
    expect(true)->toBeTrue();
});
```

```php title="tests/Feature/Http/PostApiTest.php (--phpunit)"
<?php

namespace Acme\Blog\Tests\Feature\Http;

use Acme\Blog\Tests\TestCase;

class PostApiTest extends TestCase
{
    public function test_example(): void
    {
        $this->assertTrue(true);
    }
}
```

The PHPUnit class uses the `{Root}\Tests` namespace, which `package:init` maps to `tests/` in
`autoload-dev`.

## Testing what you registered

Because the provider runs in a real application, you can test everything Anvil registered in it:

```php title="tests/Feature/RegistrationTest.php"
use Acme\Blog\Events\PostPublished;
use Acme\Blog\Listeners\NotifySubscribers;
use Acme\Blog\Models\Post;
use Illuminate\Support\Facades\Artisan;
use Illuminate\Support\Facades\Blade;
use Illuminate\Support\Facades\Event;

it('merges the config', function () {
    expect(config('blog'))->toBeArray();
});

it('registers the commands', function () {
    expect(Artisan::all())->toHaveKey('blog:sync-posts');
});

it('loads the routes', function () {
    $this->get('/blog/ping')->assertOk();
});

it('listens for events', function () {
    Event::fake();

    Event::assertListening(PostPublished::class, NotifySubscribers::class);
});

it('renders components and translations', function () {
    expect(Blade::render('<x-blog::alert />'))->toContain('<div>')
        ->and(__('blog::messages.welcome'))->toBe('Hello from blog');
});

it('creates models with the package factory', function () {
    (require __DIR__.'/../../database/migrations/create_posts_table.php')->up();

    expect(Post::factory()->create())->toBeInstanceOf(Post::class);
});
```

The migration path assumes the toolkit's timeless file names. Anvil's own integration tests use
assertions like these: see [Contributing](contributing.md#integration-tests).

## Static analysis and code style

| Tool | Config | Command |
|---|---|---|
| [Larastan](https://github.com/larastan/larastan) | `phpstan.neon.dist`: level 5, `src/` | `composer analyse` |
| [Laravel Pint](https://laravel.com/docs/pint) | `pint.json`: the `laravel` preset | `composer format` |

Every file Anvil generates passes Pint's `laravel` preset as it is, and Larastan at level 5.
Anvil's tests check both.

## Continuous integration

`.github/workflows/tests.yml` runs the test suite on every push and pull request, across the PHP
and Laravel versions you chose with `--laravel`. See
[Laravel versions](package-init.md#laravel-versions) for the matrix.
